# 定性验收期望检查清单 (Acceptance Checklist)

> **创建日期**：2026-10-27  
> **适用模块**：`koishi-plugin-patchouli-knowledge` 全链路（触发感知 / 迟智交付 / 知识沉淀）  
> **复核周期**：线上运行 24 小时后（2026-10-28 启动首次全量核查）

---

## 一、触发感知维（前端漏斗）

| 编号 | 指标名称 | 量化 / 定性判定准则 | 验证依据 / 观测手段 |
| :--- | :--- | :--- | :--- |
| **P1** | **长静默零残留** | 连续静默 $\ge 30\text{ min}$ 后的首波多人群聊（$\ge 3$ 人、短句交替），状态机必须在 $\le 90\text{ s}$ 内由 `IDLE` 切入 `BURSTING`，不得因前序高基线阻断。 | 指数衰减机制核验：首条消息基线回落至底噪 $\approx 1.0\text{/m}$；`/patchouli/api/status` 与日志验证切入时延。 |
| **P2** | **慢热讨论无漏检** | 消息速率从 $2\text{/m}$ 梯级递增至 $6\sim 8\text{/m}$ 的渐进式争论，必须在突破物理门限（$\approx 6\text{/m}$）时捕获，不得出现基线同步跟涨导致门限溢出至 $>11\text{/m}$。 | 检查上行严苛滞回闸门与预热冻结线（$0.85 \times \text{minBurstRate}$）；爬坡期基线恒低于 $1.5\text{/m}$。 |
| **P3** | **极端峰值防穿透** | 高频讨论（$\ge 11\text{/m}$）期间，突发触发门限强约束在天花板 $\le 10.8\text{/m}$（$\text{minBurstRate} \times 1.8$），严禁出现 $15\sim 28\text{/m}$ 的脱轨阈值。 | 检查突发日志中的 `describeBurst` 与 `burstThreshold` 计算结果，确认上限夹紧生效。 |
| **P4** | **低频单调收敛** | 日间峰值回落后的闲聊期（$\le 3\text{/m}$），基线必须在 15 分钟内单调下降至 $<3.5\text{/m}$，无滞回死锁。 | 下行无条件学习通道畅通，`/patchouli/api/status` 确认基线随闲聊持续平滑回落。 |

## 二、迟智与交付维（状态机周期）

| 编号 | 指标名称 | 量化 / 定性判定准则 | 验证依据 / 观测手段 |
| :--- | :--- | :--- | :--- |
| **P5** | **讨论完整性与软切片** | 单次沉淀消息量稳定落在 $15\sim 120$ 条区间；超长讨论每满 120 条触发软切片交付，相位不重置，无消息截断与丢包。 | 日志核验「开启迟智沉淀」消息数；软切片交付打 `partial: true` 标记且不触发 AIMD 调节。 |
| **P6** | **平息判定准确性** | 群聊真正静止后，必须在 $300\sim 660\text{ s}$（基础 300s + 动态语义加权）内触发 `onQuiescence`，不得出现永久卡在 `COOLING` 的悬停死锁。 | `quiescenceDeadline` 观察：到达后准时结算并解冻基线，日志打出沉淀或舍弃记录。 |

## 三、沉淀与存储维（知识落盘）

| 编号 | 指标名称 | 量化 / 定性判定准则 | 验证依据 / 观测手段 |
| :--- | :--- | :--- | :--- |
| **P7** | **双轨数据自洽** | 每次成功沉淀必须同时生成 `raw/sessions/<id>.json`（只读可信源）与 `wiki/debates/<id>.md`（双链词条），二者消息 ID 与时间戳严格对齐。 | 文件系统对齐检查：头部 `Source:` 路径有效，会话元数据与 Markdown 正文观点矩阵一致。 |
| **P8** | **索引增量闭环** | `data/llmwiki/index.md` 必须增量写入单行摘要，`data/llmwiki/log.md` 必须追加流水，且不破坏存量格式。 | git diff 或文件末尾检查：单条讨论单行记录，保持双链 `[[...]]` 与日期流水。 |
| **P9** | **静默舍弃透明度** | 讨论消息不足（$<15$ 条）或纯水群触发的丢弃，必须完整上报 `onDiscard` 诊断日志（含 `messageCount`、`peakRate`、`reason`），不得静默吞没。 | Koishi 运行日志检索：存在明确的「本轮讨论主动舍弃 (REASON，质量分 Q)」或「讨论不足未沉淀」行。 |

## 四、知识常青与公开查询维（Phase 5 / 6）

| 编号 | 指标名称 | 量化 / 定性判定准则 | 验证依据 / 观测手段 |
| :--- | :--- | :--- | :--- |
| **P10** | **归约可追溯** | 每篇常青词条的 `Sources:` 必须逐条指向已存在的 `raw/sessions/<id>.json`；被吸收的碎片正文为 `Status: superseded` 且带 `Merged-Into:`，`index.md` 不再保留旧行。 | 文件系统与 `grep` 交叉：多源路径可读、旧索引行 0 条、归并流水在 `log.md` 唯一。 |
| **P11** | **主题校准幂等与失败零写入** | 同日同群成功/无料后即封盘；进程重启不重跑；模型失败当轮不得留下半截主题或索引。 | `.patchouli/topics-state.json` 的 `dayKey/status`；失败轮前后 `wiki/debates/` 与 `index.md` 字节不变。 |
| **P12** | **卡片脱敏** | 卡片 HTML/PNG 与群内文本不出现群号、userId、metadata 或原始聊天；`superseded` 词条不参与问询。 | 卡片 HTML 断言 + 群内实发检查。 |
| **P13** | **问询零幻觉** | 检索为空时只回「馆里未曾记载过此事」，不得触发任何模型调用；多条命中必须进入编号选择态，非持态者的数字发言不被消费。 | 日志无模型调用；选择态在 5 分钟后失效；频控 3 秒 / 8 次每分钟可复现。 |
