# 帕秋莉的知识库（Patchouli Knowledge）

一个 Koishi 插件：等群里的讨论告一段落，再把大家的观点、共识和仍有争议的问题整理成可检索的本地 llmwiki 词条。

## 特性

- **按群识别讨论**：判断一轮讨论是否「值得沉淀」看的是消息里的信息量累积（势能），而不是单纯数发言条数；可以只监听指定群，不监听私聊。
- **保留不同观点**：词条把结论、分歧和原话分开记录，方便读者查看结论的依据。
- **手动记录**：遇到群会议或事先约好的讨论，管理员可以用指令指定何时开始、何时结束记录。
- **本地查阅**：可以用阅读面板按群或关键词搜索，也可以直接打开 Markdown 文件，对照来源记录核对原话。
- **跨天追踪主题**：把同一话题在不同日期的词条整理成时间轴，同时保留每篇来源词条。
- **选择模型**：复用 ChatLuna 已配置的模型和凭据，也可以不装 ChatLuna，改用自定义模型端点。

## 工作原理

插件先观察每个群平时的活跃程度，建立各自的基线。
之后每条消息会折算成「信息量」并累积成势能；势能越过本群阈值时开始收集这一轮讨论，
而不是一有人说话就动手。势能默认还会看信息的密度（单位消息的论据含量），
所以刷屏和复读不会把它推高。

发言慢下来后，它会再等一段时间（默认 300 秒），确认讨论真的结束。
讨论平息且消息数足够，插件才把这一轮交给模型；零散闲聊可以不生成词条。
移交前还有一道质量门：本轮峰值质量不足阈值的 1.2 倍就直接跳过，不烧一次模型调用。
值得保留的内容会写入本地知识库并更新索引，默认不在群里发总结通知。

判据可以通过 `trigger.triggerMode` 切换：`potential`（默认）、`rate`（纯发言频率）、
`shadow`（两套并列只观测不裁决，用于对照标定）。

## 安装

需要 Koishi `^4.18.0`，以及能接收目标群消息的机器人适配器。

**使用控制台**：在插件市场搜索 `patchouli-knowledge`，选择 `koishi-plugin-patchouli-knowledge` 安装。
先在插件配置页选好要监听的群和模型，再启用插件。

**使用命令行**：在 Koishi 实例的项目目录安装依赖，然后按下一节修改 `koishi.yml`。

```bash
pnpm add koishi-plugin-patchouli-knowledge
```

如果准备使用下面的最小配置，请先在同一个 Koishi 实例中启用 ChatLuna，并选好一个可用的默认模型。

## 最小配置

只监听一个群、用 ChatLuna 默认模型、词条发到该群相册：

```yaml
plugins:
  patchouli-knowledge:
    subscriptions:
      - source: '100000011'
        targets:
          - '100000011/<相册ID>'
        entry: true
        weekly: false
    modelConfig:
      provider: chatluna
```

订阅表里 `source` 填裸群号（`*` 表示所有群）；`targets` 是**多值**：`@chat` 表示发本群聊天，`群号/相册ID`（或控制台候选里的相册名）表示发该群相册，空数组表示只沉淀不投递。一行可以同时挂多个目标（一个群投多个相册），也可以多行指向同一相册。表为空时按旧字段 `channels` 与 `albumDelivery` 运行，升级不改变行为。

订阅表在 **Koishi Console 的插件配置页**里编辑（保存写回 `koishi.yml`）：目标从订阅表来源群的相册里选，下拉按群分组、群名那一行是不可选的分组标题，相册显示为相册名。功能总闸（`features`）同样在插件配置页。阅读浮窗只做只读展示与运行时调参，**没有订阅编辑页**。

投递策略挂在**订阅表投递群标签的右键菜单**里（不是配置页表格）：右键某个投递群标签，分别填**日词条**与**周主题**两条 5 字段 cron（如每天 22:00 → `0 22 * * *`、每周一 09:00 → `0 9 * * 1`，留空 = 该类事件立即投）与限量（词条/日、周报/周，`0` = 不限）。两条 cron 各管一类事件：改周主题不会动词条时间。策略按**（监听群 × 投递群）**各存一份：同一个相册挂在两个监听群下，各自独立定时与限额。相册名按已保存的绑定解析成稳定地址（改名 / 删除后该目标停投，重选一次即可）；四字段全留缺省 = 恢复「立即投、不限量」。保存落在知识库目录的 `.patchouli/settings.json`（`policies`），不改宿主配置。

### 哪些配置可以省略？

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 总开关。 |
| `adminUsers` | `[]` | 管理指令与自动书记的用户 ID；留空时无人可用。 |
| `subscriptions` | `[]` | 空表 = 按旧白名单 / 相册运行。 |
| `.patchouli/settings.json` 的 `policies` | 空表 | 没有策略 = 所有目标立即投、不限量。 |
| `features` | 全开 | `entries` / `weekly` / `topics` / `media` 四个启停总闸，关掉不解构任何参数。 |
| `modelConfig.provider` | `chatluna` | 使用 ChatLuna；不使用它时选 `custom`。 |
| `storage.wikiDir` | `data/llmwiki` | 知识库目录，相对于 Koishi 实例目录。 |
| `security.apiToken` | 空 | 面板与 `/api` 的密钥；为空时所有请求返回 401。 |

**换一个模型**：`modelConfig.provider` 为 `chatluna` 时选 ChatLuna 模型，或把 `modelConfig.chatlunaModel` 写成 `平台名/模型名`；省略时继承平台默认模型。

**不用 ChatLuna**：把 `modelConfig.provider` 设为 `custom`，填 `baseURL`（API 根地址）、`apiKey`（该服务的密钥，不能用面板登录密钥代替）、`customModel`（服务端识别的模型名，不加平台前缀）。

**深度参数**（触发算法、主题校准、素材池、长图、裁判服务）不在插件页，进 Console 里「LLMWiki」浮窗的齿轮「设置」页调整；它们落在 `.patchouli/settings.json`，不覆盖 `koishi.yml`。

这份文件的读写契约（面板与本文件必须一致）：

- **密钥不回显**：`media.apiKey` / `judge.apiKey` 在 `GET /api/settings` 与 `POST /api/settings` 的回包里恒为空串，同段附带 `secretConfigured: { apiKey: true | false }` 供面板显示「已配置 / 未配置」；真值只存在磁盘与运行态。
- **空串 = 不修改**：面板把回显的空串原样提交不会清空已配置密钥，提交非空值才覆盖。
- **校验在落盘之前**：字段级（长度上限 / URL 形态 / 控制字符）与合并后跨字段（`thetaMin ≥ 1e-3`、`coolingRatioThreshold < burstMultiplier`）任一不过都返回 400，文件与运行态都不变；读到历史坏值会整段丢弃并告警，插件照常启动。
- **权限 0600**：文件同 `security.apiToken` 一样按属主可读写落盘（Windows 无 POSIX 权限位，尽力而为）。

### 第一次使用怎么看效果？

1. 在白名单群里正常聊天。默认按信息势能触发，不是凑够几条消息就立即生成词条。
2. 等讨论平息。自动记录默认至少需要 12 条消息，平息观察期默认是 300 秒。
3. 有新词条后，从知识库的 `index.md` 查看索引；启用 Koishi 网页服务后，也可以在 Console 里打开「LLMWiki」浮窗查阅。

想使用浮窗时，可以在插件配置页设置专用密钥 `security.apiToken`，然后按浮窗提示登录。
浮窗的群聊筛选适合找某个群的讨论；记得原话但忘了标题时，可以用关键词搜索正文。

### 数据保存在哪里？

下列路径都相对于 `storage.wikiDir`：

| 路径 | 内容 |
| --- | --- |
| `index.md` | 已生成词条的索引和摘要。 |
| `wiki/debates/` | 可用普通文本编辑器打开的 Markdown 词条。 |
| `raw/sessions/` | 与词条对应的原始会话记录。 |
| `log.md` | 按时间追加的知识库写入记录。 |

本地存储不等于离线处理：整理讨论时，群消息会提交给你选择的模型。
启用前请告知群成员，并限制知识库目录和备份的访问权限，尤其不要公开原始会话。

## 指令

按机器人配置的 Koishi 指令前缀调用；表中只列指令名。

| 指令 | 谁能用 | 用途 |
| --- | --- | --- |
| `patchouli` | 所有用户 | 查看插件简介、阅读面板入口及指令提示。 |
| `patchouli.status` | 管理员 | 查看本群当前状态、发言速率和已缓冲的消息数。 |
| `patchouli.logon` | 管理员 | 立即开始记录本群接下来的讨论，不必等发言变密。 |
| `patchouli.logoff` | 管理员 | 结束手动记录，将讨论交给模型整理；不足 2 条则丢弃。 |

这里的管理员指列入 `adminUsers` 的用户，不是群聊平台上的管理员角色。
要试用手动记录，请在配置页添加自己的用户 ID，再到已监听的群里执行 `patchouli.logon`；讨论结束时执行 `patchouli.logoff`。

## 开发

在插件源码目录运行以下命令。项目使用 pnpm，CI 在 Node.js 22 和 24 上运行。

```bash
# 按锁文件安装开发依赖
pnpm install --frozen-lockfile

# 编译插件并同步控制台客户端资源
pnpm build

# 运行测试（先构建）
pnpm test

# 只做 TypeScript 类型检查，不输出文件
pnpm typecheck
```
